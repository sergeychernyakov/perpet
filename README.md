## Как сделаны примеры

### Aeterna: Rails-приложение

«Цифровой семейный архив воспоминаний».

| Область | Как сделано |
| --- | --- |
| Стек | Ruby 3.4.5, Rails 8.1, SQLite, Propshaft + importmap, Turbo + Stimulus |
| Вход и роли | Devise (+ devise-i18n, russian), CanCanCan, флаг `admin` у пользователя |
| Админка | Свой namespace `/admin` со scaffold-CRUD основных сущностей |
| API | `/api/v1/*` в JSON: регистрация, вход, проверка токена, выход; записи: список, просмотр, создание, изменение. JWT в заголовке `Authorization: Bearer`, CORS через rack-cors |
| Файлы | CarrierWave (+ оптимизация картинок), Active Storage для аватаров |
| Сиды | Пересоздают БД и чистят загрузки. Создают админа, 6 пользователей с профилями и аватарами, семью с родственными связями, по 5–15 записей на человека со случайными текстами, картинками и 1–3 тегами, подборки записей |
| Вёрстка | Свой CSS без фреймворков: переменные, базовые стили, файл на каждую страницу, свои шрифты, медиазапросы |
| Интерактив | Stimulus-контроллеры (dropdown, flash, копирование, фильтр, parallax), комментарии через Turbo Streams |
| Прочее | Онбординг после регистрации, профиль, теги (acts-as-taggable-on), SEO (meta-tags) |
| Инфраструктура | GitHub Actions (brakeman, bundler-audit, rubocop, тесты), Dockerfile, Kamal |

### Aeterna-MiniApp: мини-приложение

| Область | Как сделано |
| --- | --- |
| Основа | [ZakharDay/static-site-boilerplate](https://github.com/ZakharDay/static-site-boilerplate): Webpack 5, Babel, PostCSS, многостраничный статический сайт |
| UI | HTML-страницы и React 19 для интерактивных частей (форма создания записи). Компоненты названы по атомарному дизайну: `A_Button`, `M_Form`, `O_MemoryFormContainer` |
| Работа с API | `fetch`: вход или регистрация → JWT в cookie → запросы с `Authorization: Bearer` |
| Страницы | Лендинг с формами входа и регистрации, список записей, карточка записи, создание записи |
| Адаптив | Отдельный `responsive.css`, брейкпоинты 1024 и 768 px |
| Деплой | GitHub Pages: сборка в `docs/` через GitHub Actions |

### Слабые места примеров

Здесь можно сделать лучше:

- Адрес API захардкожен как `http://localhost:3000`: мини-приложение получает данные только на машине разработчика.
- CORS разрешён только для `http://localhost:8080` и только для GET и POST.
- VK Bridge не подключён: по сути это обычный сайт.
- Картинки для сидов (`public/autoupload`) лежат в `.gitignore`, поэтому на свежем клоне `db:seed` упадёт.
- Админка не закрыта ролью: обычный пользователь попадает в `/admin` и в списке записей видит записи всех семей.
- Тесты — заготовки генератора, часть ссылается на удалённое поле `author`.
- README Rails-приложения — одна строка, у мини-приложения остался README бойлерплейта.

## VK: что учесть заранее

- Мини-приложение в VK открывается по HTTPS. Чтобы оно получало данные у проверяющего и на телефоне, Rails-приложение нужно развернуть на публичном HTTPS-домене. Для разработки есть `@vkontakte/vk-tunnel`.
- При старте мини-приложение вызывает `VKWebAppInit` из `@vkontakte/vk-bridge`.
- Пользователя можно опознавать по параметрам запуска (`vk_user_id` и подпись `sign`), а подпись проверять на сервере защищённым ключом приложения. Тогда в мини-приложении не нужны email и пароль.
- На vk.com мини-приложение открывается в iframe, где cookies могут блокироваться, например в Safari. Токен надёжнее хранить через VK Bridge Storage или localStorage.
- Мини-приложение нужно зарегистрировать в VK, инструкция на dev.vk.com.
