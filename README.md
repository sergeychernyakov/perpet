# PERPET

Сервис передержки животных: объявления о поиске временных хозяев, статьи, профиль питомца
и поддержка. Состоит из двух частей:

- **сайт** на Ruby on Rails 8 с базой SQLite, админкой и API — папка репозитория целиком;
- **мини-приложение ВКонтакте**, которое работает с сайтом по этому API — папка `miniapp/`.

Свёрстано по макету из Figma, без UI-фреймворков: только свои стили по токенам макета.
Палитра и типографика — как в исходном файле: кремовый `#F8F3E0`, коралловый `#FF8282`,
салатовый `#BCE29B`, текст `#434343`; заголовки — OvalCyr (в вебе его нет, подставлен Nunito),
текст — Comic Relief и Arsenal SC, служебные подписи — Anonymous Pro.

| Слой | Чем сделано |

Внешних зависимостей минимум: нет ни гема админки, ни фронтенд-фреймворка, ни сборщика.

## Запуск

```bash
bundle install
bin/rails db:prepare
bin/rails db:seed
bin/rails server
```

Сайт поднимется на http://localhost:3000 уже с данными: 22 объявления (19 питомцев
и 3 ситтера) с фотографиями из макета, 18 статей, 6 вопросов в FAQ, 3 канала
поддержки, семь пользователей и профили с объявлениями.

### Логины

Вход идёт по логину, почта нужна только для восстановления пароля.
`bin/rails db:seed` заводит учётные записи с паролем `perpet123`:

| Логин | Кто это | Что доступно |
| --- | --- | --- |
| `admin` | администратор | всё, включая раздел `/admin` |
| `anna` | обычный пользователь | профиль и свои объявления |
| `maria` | Мария из макета | профиль, карточка ситтера |
| `mixi` | Михаил из макета | четыре карточки питомцев |
| `petr`, `margarita`, `anastasia` | ситтеры из макета | свои карточки |

### Вход в админку

1. Открыть http://localhost:3000/users/sign_in
2. Войти как `admin` / `perpet123`
3. В шапке появится пункт **«Админка»** — он виден только администраторам.
   Прямой адрес: http://localhost:3000/admin

Гостя раздел отправляет на страницу входа, обычного пользователя — на главную
с предупреждением «Раздел доступен только администраторам».

Сделать администратором любого другого пользователя:

```bash
bin/rails runner 'User.find_by(email: "kto@mail.ru").update!(role: :admin)'
```

## API для мини-приложения

Все адреса под `/api/v1`, ответы в JSON.

| Метод | Адрес | Вход нужен | Что делает |
| --- | --- | --- | --- |
| GET | `/api/v1/ads` | нет | Каталог: `kind`, `q`, `page` |
| GET | `/api/v1/ads/:id` | нет | Одно объявление |
| GET | `/api/v1/ads/mine` | да | Свои объявления |
| POST | `/api/v1/ads` | да | Создать черновик |
| PATCH | `/api/v1/ads/:id` | да | Изменить своё |
| DELETE | `/api/v1/ads/:id` | да | Удалить своё |
| GET | `/api/v1/articles`, `/api/v1/articles/:id` | нет | Статьи и текст статьи |
| GET / PATCH | `/api/v1/profile` | да | Профиль текущего гостя из VK |
| GET | `/api/v1/support` | нет | Каналы связи, FAQ, темы обращений |
| POST | `/api/v1/leads` | нет | Заявка или отклик |
| POST | `/api/v1/support_tickets` | нет | Обращение в поддержку |

### Как устроен вход из VK

Отдельного логина нет — ВКонтакте сам сообщает, кто пришёл:

1. VK открывает мини-приложение и дописывает в адрес параметры запуска:
   `vk_user_id`, `vk_app_id`, `vk_ts`, `vk_platform` и подпись `sign`.
2. `sign` — HMAC-SHA256 от отсортированных `vk_*` параметров, подписанный защищённым
   ключом приложения. Ключ знают только VK и сервер.
3. Мини-приложение пересылает строку целиком в заголовке `X-VK-Launch-Params`.
4. Сервер пересчитывает подпись своим `VK_APP_SECRET` и сравнивает. Совпало и параметрам
   меньше суток — значит `vk_user_id` настоящий.
5. При первом заходе заводится учётная запись с этим `vk_id` и профиль к ней.

Без верной подписи API отвечает 401. В разработке ключа нет, и проверка не включается —
достаточно `vk_user_id`, чтобы удобно отлаживать:

```bash
curl -H 'X-VK-Launch-Params: vk_user_id=501&vk_app_id=54774841' \
     http://localhost:3000/api/v1/profile
```

## Мини-приложение ВКонтакте

Лежит в `miniapp/`, подробности — в `miniapp/README.md`. Выложено на приложение
заказчика **54774841**.

Оболочка приложения живёт на хостинге VK и обновляется только командой
`npm run deploy`; данные — статьи, объявления, профили — приложение берёт у сайта
по API, и они приезжают сразу после `bin/deploy`. Стили и картинки `build.js`
копирует с сайта в сборку, поэтому правка вёрстки доезжает до ВКонтакте тоже
только выкладкой.

Приложение повторяет сайт один в один: `build.js` кладёт в сборку его стили и картинки
(`app/assets/stylesheets` → `css/`, `app/assets/images` → `assets/`), а экраны собираются
теми же классами, что и вьюхи Rails. Своей копии оформления нет, расходиться нечему.

Экраны: главная, объявления с фильтрами и откликом, статьи и страница статьи, «О нас»,
бренд-бук, профиль со своими объявлениями, поддержка с FAQ и формой обращения. Шапка,
меню и подвал — сайтовые, переходы через `location.hash`.

Что берётся у ВКонтакте: имя и город подставляются в профиль и в форму отклика, почту
можно взять одной кнопкой, показывается аватарка (или инициалы, если фото нет),
объявлением можно поделиться ссылкой вида `#ad/:id`. Тему приложение берёт из клиента
VK — светлую или тёмную.

```bash
cd miniapp
npm start      # соберёт и раздаст локально на http://localhost:5173
npm run deploy # выкладка на хостинг VK
```

Deploy спрашивает имя тестовой группы (любое), на «update test group url?» отвечаем
**n**, на остальное `y`, а код подтверждения приходит в чат «Администрация ВКонтакте».

## Фотографии

К объявлению и к питомцу в профиле можно приложить снимок. Уменьшает его браузер
перед отправкой — до 1400 px и JPEG 0.82: на сервере нет ни libvips, ни места под
оригиналы. Снимок 1600×1600 весом 155 КБ уезжает как 33 КБ. Сервер проверяет тип
и предел 3 МБ на случай запроса мимо интерфейса. Карточка без фотографии показывает
силуэт из макета.

Фотографии в каталоге и в профилях достались из `design/Untitled.fig` — снимки лежат
прямо в архиве макета — и перечислены в `db/seeds.rb`: `PET_PHOTOS` привязывает файл
к названию объявления, у людей файл указан в `PEOPLE`. Птиц в макете нет, поэтому трём
карточкам с попугаями достался оттуда же рисунок с кореллой.

## Данные

`db/seeds.rb` пересоздаёт всё с нуля: объявления по городам и видам питомцев, статьи
с тегами и временем чтения, вопросы поддержки, каналы связи, двух пользователей
и профиль с объявлениями.

Модели: `User`, `Profile`, `Ad`, `Article`, `FaqItem`, `SupportChannel`, `SupportTicket`,
`Lead`. Оформление главной и страницы «О нас» (преимущества, промо-карточки, шаги)
живёт в коде как `Data.define` — это вёрстка, а не данные сервиса.

### Разметка статьи

В макете у каждой статьи своя раскладка, поэтому текст в админке набирают обычными
абзацами, а блоки размечают в начале строки — разбирает это `Article#layout`:

| Метка | Что получится |
| --- | --- |
| `## Заголовок` | коралловая полоса раздела во всю ширину |
| `@@ Заголовок` | плашка с заливкой: заголовок и текст внутри |
| `@ Заголовок` | панель с заголовком сбоку, содержимое рядом |
| `### Заголовок` | колонка: рамка с заголовком внутри |
| `#### Заголовок` | колонка: салатовая плашка-заголовок над содержимым |
| `! Текст` | салатовая плашка с крупной мыслью |
| `+ Текст` | салатовая плашка с обычным текстом |
| `- пункт` | пункты-«пилюли» |
| `---` | конец ряда |

Идущие подряд колонки встают в один ряд, цвет панелей чередуется салатовый —
коралловый. Отдельной строкой внутри блока ставят пометки: `~ cat`, `~ plus`,
`~ minus`, `~ hand`, `~ hand-right` — какой рисунок у блока; `~ lime` и `~ coral` —
цвет, если он выбивается из чередования; `~ side` и `~ side-lead` — заголовок плашкой
слева, содержимое рядом; `~ plain` — текст панели обычный, а не заголовком; `~ lead` —
первый абзац внутри самой панели; `~ check` — пункты в два столбца с кружком-стрелкой.

Поиск по объявлениям работает по отдельному полю `search_text`: SQLite приводит
к нижнему регистру только латиницу, поэтому строка для поиска готовится заранее.

## Выкладка

Сайт живёт на сервере рядом с другими проектами: `deploy@195.19.209.216`,
каталог `/var/www/perpet`. Подробности и переменные окружения — в `DEPLOY.md`.

```bash
bin/deploy          # запушить, обновить сервер, перезапустить
bin/deploy --seed   # то же плюс пересоздать демонстрационные данные
```

`--seed` стирает и заведённые аккаунты. Чтобы обновить только содержимое —
статьи, объявления и демо-людей из макета, — на сервере хватит одного раздела:

```bash
ssh deploy@195.19.209.216 'cd /var/www/perpet && RAILS_ENV=production SEED=content bundle exec rails db:seed'
ssh deploy@195.19.209.216 'cd /var/www/perpet && RAILS_ENV=production SEED=articles bundle exec rails db:seed'
```

## Заметки по работе

- Тексты заказчика перенесены из макета дословно, включая «обьявления», «обьединяет»
  и «отьезд» через мягкий знак: так они написаны в Figma. Исправить — заменить `ь` на `ъ`
  в `app/views` и `app/models/{promo,step,brand}.rb`.
- Крупные блоки выложены в долях от своей ширины (`container-type: inline-size` и `cqw`),
  как в макете: композиция одинаково собрана и на ноутбуке, и на большом мониторе.
  Для узкого экрана у обложки, «Проблемы», «ВАЖНО» и цитаты есть отдельная раскладка.
- Гем `json` зафиксирован на версии 2.x: в 3.0 изменилась сигнатура `JSON.parse`,
  из-за чего Rails 8.1 падает при чтении сессии. Dependabot про 3.x не предлагает.
- Мост VK лежит рядом с файлами мини-приложения, а не тянется с CDN: сторонний хост
  может не открыться, и тогда приложение не пришлёт `VKWebAppInit`.
- Фото питомца из Claude Design скачивалось обрезанным (лимит 256 КБ), поэтому взято
  из исходного файла Figma и сохранено в JPEG.
