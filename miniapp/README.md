# Мини-приложение PERPET для VK

Статическая страница без сборки: VK Bridge лежит рядом с файлами, данные берутся
из API основного сайта (`/api/v1`).

Оформления своего у приложения нет — `build.js` кладёт в сборку стили и картинки
сайта (`app/assets/stylesheets` → `css/`, `app/assets/images` → `assets/`), а экраны
собираются теми же классами, что и вьюхи Rails. Правка на сайте автоматически
приезжает в приложение следующей сборкой; в `app.css` остаётся только то, чего на
сайте нет: карточка поверх экрана, заглушки и мелочи под ВКонтакте.

## Экраны

| Экран | Что умеет |
| --- | --- |
| Главная | обложка, преимущества, диаграмма, промо-карточки, «ВАЖНО» |
| Объявления | каталог с фотографиями, фильтр по виду, поиск, «Показать ещё», отклик, «Поделиться» |
| Статьи | список блоками во всю ширину и страница статьи |
| О нас | проблема, преимущества, статистика, шаги передержки, цитата |
| Brand book | логотип, палитра, фирменная графика, суть и ценности, мерч |
| Профиль | имя и аватарка из VK, данные питомца, свои объявления, черновик с фотографией |
| Поддержка | каналы связи, частые вопросы, форма обращения |

Переходы — через `location.hash` (`#ads`, `#article/12`), шапка и подвал такие же,
как на сайте: логотип, меню, бургер на узком экране.

## Локальная отладка

```bash
npm start                       # соберёт build/ и раздаст на http://localhost:5173
```

Откройте с адресом своего API и подставленными параметрами запуска:

```
http://localhost:5173/index.html?api=http://localhost:3000&vk_user_id=501&vk_app_id=54774377
```

`http://localhost:5173` уже разрешён в `CORS_ORIGINS` по умолчанию, поэтому
локальное приложение ходит в локальный Rails без настройки.

Без `VK_APP_SECRET` сервер в разработке подпись не проверяет, поэтому хватает
`vk_user_id`. В production без верной подписи API отвечает 401.

## Выкладка на хостинг VK

```bash
npm run deploy                  # сборка в build/ и заливка
```

Что спросит `vk-miniapps-deploy` при первом запуске:

| Вопрос | Ответ |
| --- | --- |
| `Enter test group name` | любое имя, например `perpet` |
| `Do you want to update test group url?` | **n** — иначе адрес тестовой группы перезапишет боевой |
| остальные подтверждения | `y` |
| код подтверждения | придёт в чат «Администрация ВКонтакте» |

Выйти из аккаунта и зайти другим — `npx @vkontakte/vk-miniapps-deploy login`;
токен лежит в `~/.config/configstore/@vkontakte/vk-miniapps-deploy.json`.

`npm run deploy -- --production` переводит залитую версию в боевую.

### Куда выкладывается

`vk-hosting-config.json` указывает на приложение **54774377** и на папку `build/`.
Приложение заказчика — **54774841**; чтобы выкладывать туда, нужны права
администратора или редактора в его настройках на dev.vk.com, иначе deploy отвечает
`Permission ... User should be admin or editor of application`. Как дадут права —
поменять `app_id` в `vk-hosting-config.json` и `VK_APP_ID` в `config.js`.

## Что нужно, чтобы заработало внутри VK

1. У основного сайта должен быть **HTTPS на своём домене** — VK не пускает
   ни `http://`, ни адрес по IP. Значит, сначала A-запись `perpet` и сертификат
   (см. `../DEPLOY.md`).
2. Домен мини-приложения должен быть в `CORS_ORIGINS` на сервере — сейчас там
   разрешены `https://*.vk-apps.com`, `https://*.vk-apps.ru` и `https://vk.com`.
3. `VK_APP_SECRET` на сервере — уже прописан.
